二、V2.0 开发计划
-----------------------------------------------

1. 工具调用 (Function Calling)
-----------------------------------------------
【概述】
让 AI 模型能够调用外部工具（函数），实现更智能的交互。例如调用获取天气、查询数据库、执行计算等。

【1.1 工具定义机制】
- 定义 Tool 实体/接口规范，支持 JSON Schema 格式的工具描述
- 支持工具注册（注解扫描 + 手动注册两种方式）
- 内置常用工具（获取时间、数学计算、字符串处理等）

【1.2 工具执行引擎】
- 解析 AI 模型返回的 function_call 请求
- 调用对应工具函数并获取结果
- 将工具结果作为上下文继续对话
- 支持同步和异步工具调用

【1.3 可扩展工具接口】
- 定义 ToolProvider 接口，便于开发者添加自定义工具
- 支持 REST API 作为外部工具调用
- 工具调用权限管理（管理员可见/用户可见）

【1.4 前端展示】
- 工具调用可视化：展示 AI 调用了什么工具、输入输出
- 用户可手动触发/禁止特定工具

实现方式：后端新增 tool 包（model/entity、service、provider），修改 ChatService 流式/非流式逻辑；
前端中 tool 调用可视化在聊天消息中展示。

2. RAG 知识库
-----------------------------------------------
【概述】
实现检索增强生成（Retrieval-Augmented Generation），让 AI 能够基于用户上传的文档回答问题。

【2.1 文档管理】
- 支持上传 TXT、PDF、Markdown 格式文档
- 文档列表管理（查看/删除/重新索引）
- 文档分块（Chunking）：按段落/固定大小切分
- 每个知识库关联多个文档

【2.2 向量存储与检索】
- 集成嵌入模型（Embedding Model）进行文本向量化
- 向量数据库存储（可选用 ChromaDB / PostgreSQL pgvector / FAISS 本地）
- 语义检索：基于余弦相似度检索最相关的 Top-K 文档片段
- 检索结果注入对话上下文

【2.3 知识库管理】
- 用户可创建多个知识库
- 知识库 CRUD（创建/编辑/删除）
- 知识库权限控制（私有/公开）
- 管理后台可查看所有知识库

【2.4 对话中引用】
- 用户在对话中可启用/切换知识库
- AI 回复时显示引用来源（文档名称、原文段落）
- 支持 Token 消耗统计（嵌入计算 + 检索消耗）

【2.5 技术选型建议】
- 嵌入模型：本地部署 bge-small-zh / text-embedding-ada-002 API
- 向量数据库：ChromaDB（轻量、可嵌入 Spring Boot）
- 分块策略：按段落（\n\n）分割 + 重叠窗口

3. 长记忆对话方案
-----------------------------------------------
【概述】
当前仅保留最近 30 条消息作为上下文。长记忆方案让 AI 能够"记住"更早期的对话内容。

【3.1 对话摘要机制】
- 当历史消息超过阈值（如 20 条）时，启动摘要生成
- 使用 AI 模型自动总结历史对话要点
- 将摘要作为系统提示词注入，替代部分历史消息
- 定期更新摘要（每新增 10 条消息刷新一次）

【3.2 分层记忆架构】
- 短期记忆：最近 30 条消息（当前实现）
- 中期记忆：对话摘要（新增）
- 长期记忆：关键信息提取（用户偏好、事实性信息）

【3.3 关键信息提取】
- 从对话中自动提取关键信息（用户喜好、重要事实）
- 存储为结构化 Key-Value 对
- 在后续对话中作为上下文注入

【3.4 记忆管理界面】
- 用户可查看/编辑 AI 记住的信息
- 手动添加关键记忆
- 清除特定记忆或全部记忆
- 记忆开关（用户可选择关闭长记忆功能）

【3.5 数据库设计】
- 新增 conversation_summary 表（对话ID、摘要内容、版本号、更新时间）
- 新增 memory_items 表（用户ID、对话ID、Key、Value、类型、创建时间）

4. 图像识别（多模态）
-----------------------------------------------
【概述】
让 AI 能够"看懂"用户上传的图片，支持图像识别、图片描述、图片分析等功能。

【4.1 图片上传与预览】
- 聊天窗口中支持上传图片（拖拽/点击上传）
- 图片预览（缩略图/放大查看）
- 支持格式：PNG、JPG、JPEG、GIF、WEBP
- 图片大小限制（可配置，默认 10MB）

【4.2 多模态 AI 接入】
- 支持多模态模型 API（如 GPT-4V、Claude Vision、千帆多模态）
- 将图片作为消息的一部分发送给 AI 模型
- 支持单图/多图分析

【4.3 图片管理】
- 聊天历史中的图片记录与展示
- 上传图片的存储与管理（复用现有上传机制）
- 定期清理未关联的图片文件

【4.4 收费策略】
- 图片上传消耗额外 Token
- 按图片尺寸/清晰度分级计费
- 管理后台可配置图片处理单价

四、技术要点与依赖
-----------------------------------------------
【工具调用】
- 依赖：AI 模型需支持 function_call（GPT-4、Claude、千帆等均支持）
- 实现方式：在 API 请求中附带 tools 参数，解析返回的 tool_calls

【RAG 知识库】
- 依赖：嵌入模型 + 向量数据库
- Spring Boot 集成 ChromaDB：通过 HTTP API 或嵌入式模式
- 第三方库：langchain4j（Java 版 LangChain）可大幅简化实现
- 不引入 langchain4j 时：手动调用 Embedding API + 自行管理向量存储

【长记忆】
- 依赖：AI 模型自身（用于生成摘要）
- 前端需要增加记忆管理界面

【图像识别】
- 依赖：多模态 AI 模型 API（GPT-4V、Claude 3 Vision 等）
- 图片处理：可直接用 Base64 编码发送，或使用图片 URL

五、与 V1.0 的衔接
-----------------------------------------------
V2.0 完全基于 V1.0 已有架构扩展，不破坏现有功能：

- 工具调用 → 扩展 ChatService 的 buildMessagesArray 逻辑
- RAG 知识库 → 新增独立模块，对话侧加入知识库选择
- 长记忆 → 扩展 Conversation 模型，新增 summary 和 memory 表
- 图像识别 → 扩展 ChatRequest DTO 增加图片字段
- 功能优化 → 直接在现有代码基础上增强
- 前端优化 → 扩展现有 CSS/JS，不重构
